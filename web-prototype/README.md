# 布局原型（PROTOTYPE，用完即弃）

回答的问题：第一期各页面应该长什么样，尤其是分支谱系视图怎么呈现。依据 `docs/design/v1-scope.md`「原型」一节，术语以 `GLOSSARY.md` 为准。

只存在于 `prototype/layout` 分支，不合入 main。选定方案后在正式代码里重写。

## 运行

```
pnpm prototype          # 仓库根目录；或 cd web-prototype && pnpm dev
```

打开 http://localhost:5199 。数据全部在内存里，刷新即重置。

- 底部黑条是原型工具，不属于设计：切换视角（管理员 / Owner / PE），权限不同页面会变。
- 应用详情页 `/apps/billing-core?variant=A|B|C` 切换三种谱系视图，也可以用 ← → 键。
  - A 泳道时间轴：每条线一行，按发布先后横向排列，分叉连线从源版本引出。
  - B 按源版本缩进：版本自上而下，维护线缩进在源版本下面。
  - C 表格 + 详情栏：每条线一行，源版本作为一列，可按状态筛选、按计划终止日期排序。
- `计费核心` 的假数据覆盖：三层嵌套的维护线、同一版本分叉出两条线、冻结和终止的线、分叉后还没有版本的线、5 天和 14 天后到期的线、不规则版本号（`R5SP2`、`v2026.08`）、tag 和 commit 混用。`订单服务` 的主线分支名是 `develop`。
