# LDAP 用户优先占用用户名，冲突时拒绝登录并交给管理员处理

> 第二期更新（#29）：本地身份改名为邮箱身份，用登录邮箱加密码登录，不再用用户名登录（见 `docs/design/iam-scope.md`）。下文中的“本地账号”“本地用户”分别指邮箱身份、只有邮箱身份的用户。

LDAP 首次登录时，如果登录名与某个已有本地用户的用户名相同，系统拒绝这次登录，不创建用户也不绑定身份，提示联系管理员。同名的两个账号可能是同一个人，也可能是两个人，系统判断不了（ADR-0002 不允许按邮箱或用户名自动合并），只能交给人判断：是同一个人时，管理员把 LDAP 身份绑定到已有用户；是两个人时，管理员把本地用户改名，之后 LDAP 用户再正常首次登录。为了让冲突尽量少，管理员创建本地用户时会先查 LDAP，目录里已有同名登录名的就不允许创建，因为 LDAP 是公司统一的命名空间，本地账号只服务于不在 LDAP 里的人。我们否决了"自动加后缀"（如 `jdoe-2`）的方案：两个形近的用户名会让 Owner/PE 选错人，而且先建的本地账号能永久抢占真正 LDAP 用户的名字。

## Consequences

- 管理员可以修改纯本地用户（没有绑定 LDAP 身份）的用户名；绑定了 LDAP 的用户，用户名不可修改。
- 系统内部的所有关联（Owner/PE、变更历史、登录身份）都用用户 ID，不用用户名，所以改名不会影响历史记录。
- 创建本地用户依赖目录适配器的登录名查询能力；LDAP 不可达时，创建本地用户失败并给出明确错误，而不是跳过检查。
- 用户名虽然不再用于登录邮箱身份，但仍在全体用户中唯一，用于展示和挑选 Owner/PE，因此本 ADR 的冲突规则不变。
- 本地用户也可以先用本地账号登录，再在个人设置里绑定 LDAP 身份（必须用 LDAP 完成认证），自行解决冲突。
