# 第二期范围：IAM（grill 会话结论，2026-10-14）

术语以 `GLOSSARY.md` 为准；关键取舍见 `docs/adr/0005`–`0007`；调研见 `docs/research/iam-auth-mfa.md`、`avatar-object-storage.md`、`iam-org-rbac.md`。

## 定位

- IAM 是本工具内部的一个模块，只服务本工具，不对外提供 OIDC/SSO。
- 第一期按原计划实现；第二期叠加在第一期之上。唯一提前落到第一期的是"本地身份改为邮箱身份"（见下文），因为第一期还没实现本地登录，现在改没有迁移成本。
- 界面延续 Console 风格（原型方案 A），只做浅色主题。

## 登录身份

- 登录身份有两种：LDAP 身份、邮箱身份。每个用户每种最多一个，绑定和解绑沿用 ADR-0002，最后一个身份不能解绑。
- 邮箱身份 = 登录邮箱 + 密码，只能用登录邮箱登录，不能用用户名登录。不做免密登录（邮件验证码、登录链接）。
- 登录邮箱在所有邮箱身份中唯一，必须已验证：
  - 管理员创建或修改的登录邮箱视为已验证。
  - 用户自己绑定邮箱身份或修改登录邮箱，必须收验证码确认；修改时通知旧地址。SMTP 未配置时这两个功能不可用。
  - 初始管理员的登录邮箱来自配置文件，视为已验证。
- 联系邮箱属于用户资料：绑定了 LDAP 的用户以 LDAP 为准，登录时同步；否则等于登录邮箱，用户不能单独修改，只能通过修改登录邮箱（需验证）来改变。联系邮箱不要求唯一，LDAP 同步不会改动任何人的登录邮箱。
- 用户名仍然在全体用户中唯一，用于展示和挑选 Owner/PE；ADR-0004 的冲突规则不变。管理员创建邮箱身份用户时一并填写用户名。
- 不开放自助注册。邮箱身份用户只能由管理员创建：
  - SMTP 已配置：发邀请邮件，用户通过链接设置密码。
  - SMTP 未配置：管理员设置临时密码，用户首次登录必须修改。
- LDAP 用户可以在个人设置里追加邮箱身份。
- 找回密码只对邮箱身份有效，需要 SMTP；对外统一返回通用提示，防止枚举邮箱。

## 二次验证

- 二次验证属于用户，不属于登录身份；无论用哪个登录身份登录，开启后都要验证。
- 方式只有验证器（TOTP：SHA1、30 秒、6 位，允许前后各一个时间步，同一时间步的码只能用一次）和恢复码（一次性，哈希存储）。邮件验证码不作为二次验证方式，不做"记住此设备"（ADR-0006）。数据模型为以后的通行密钥预留位置。
- 启用流程：重新输入密码 → 扫码 → 输对一次验证码才正式启用 → 只展示一次恢复码 → 邮件通知（SMTP 已配置时）→ 记入审计。
- 第一因素通过后只发一个短期令牌，用于提交二次验证；通过后才发正式会话。
- 失败次数按用户累计，达到阈值后锁定该用户的二次验证一段时间。
- 强制策略三层：用户自选开启；管理员可对全体强制开启；管理员角色的用户始终强制开启。被强制但尚未启用的用户，登录后只能进入启用流程。
- 管理员可以重置别人的二次验证：通知本人，记入审计。
- 容器内提供命令行，用于唯一管理员被锁在外面时重置其二次验证或密码。

## 邮件

- 只发认证和安全相关邮件：邀请、验证邮箱、找回密码、二次验证启用/重置、登录身份绑定/解绑、登录邮箱修改。不发业务通知。
- 管理后台配置 SMTP：主机、端口、加密方式（465 隐式 TLS / 587 STARTTLS；不加密需要显式勾选）、用户名、密码、发件人、可选自定义 CA；不提供跳过证书校验。提供"发送测试邮件"，使用未保存的表单内容。
- 发信走数据库发件队列，后台任务发送并重试。
- 模板打包在程序里，HTML + 纯文本，中英各一份，按收件人的语言偏好（第一期 #15 已保存在用户上）发送。
- 邮件中的链接用管理员配置的站点外部地址拼接，不用请求的 Host 头。

## 系统配置

- LDAP、SMTP、对象存储都在管理后台配置并存入数据库（ADR-0005），取代第一期"LDAP 参数放在配置文件"。每项都有"测试连接"。
- 密码、令牌、访问密钥用 AES-256-GCM 加密存储，主密钥来自环境变量或 Docker secret；接口只写不读。
- 配置文件只保留数据库连接、主密钥、初始管理员。
- 配置变更记入审计。

## 头像

- 存储：一套 S3 兼容实现覆盖阿里云 OSS、腾讯云 COS、MinIO；未配置对象存储时退回本地磁盘。存储桶私有并阻止公共访问（ADR-0007）。
- 上传经过后端：最大 2MB；按文件头识别格式，只接受 jpeg、png、webp，拒绝 SVG；解码前检查像素数防解压炸弹；按 EXIF 方向转正后裁成 256px 正方形，重新编码，元数据随之去除。上传按用户限流。
- 下载经过后端鉴权：`/api/avatars/{id}?v={hash}`，校验登录状态后返回，长期缓存。
- 每个用户只保留一个当前头像对象；替换时先写新对象再删旧对象，定时清理孤儿对象。
- 显示优先级：用户上传的头像 > LDAP 照片（`thumbnailPhoto`/`jpegPhoto`，同样经过处理流程）> 显示名首字母。

## 组织架构

- 组织架构是一棵在本工具中维护的部门树，只用于展示、筛选和挑选用户，不参与授权。不从 LDAP 同步（数据模型预留来源和外部 ID）。
- 每个用户最多属于一个部门，由管理员指定。这一期不设部门负责人。
- 第一期用户身上的"部门"字段改名为目录部门：LDAP 同步来的只读文字，与组织架构无关。
- 部门可以新建、改名、移动、删除；有成员或子部门的部门不能删除。

## 角色与权限

- 管理员、Owner、PE 是不可删除的内置角色。权限点定义在代码里，每个角色是一组权限点。
- 角色只授给个人（Owner/PE 的范围是某个应用，管理员是全局）。
- 管理后台的"角色"页只读，展示每个角色包含的权限点。
- 不做：自定义角色、按部门授权、按数据范围过滤、Casbin。
- 所有登录用户都能看到全部应用，应用不设所属部门。

## 审计

- 记入审计：登录身份绑定/解绑、二次验证启用/重置、管理员重置密码、角色和 Owner/PE 变更、部门变更与成员调整、系统配置变更。记录操作人和时间。
- 管理后台提供审计日志页，按操作人、对象、时间筛选。

## 页面

- 个人设置分四个标签页：资料（含头像）、登录身份、安全（二次验证、恢复码、修改密码）、偏好（语言）。
- 管理后台在"代码平台""用户"之外新增：部门、角色（只读）、LDAP、邮件、存储、安全策略、审计日志。
- 登录页：LDAP 和邮箱两种方式切换；二次验证输入页；找回密码与设置密码页（邀请链接共用）。
