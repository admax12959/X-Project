# 第一期范围（grill 会话结论，2026-10-10）

术语以 `GLOSSARY.md` 为准；关键取舍见 `docs/adr/`。

## 技术栈

- 后端：Go，REST API
- 前端：React + Vite 单页应用 + Base UI（`@base-ui/react`，原 `@base-ui-components/react` 已改名）+ Tailwind，TypeScript
- 数据库：MySQL 8
- 部署：内网，Docker
- 界面语言：中文和英文，用户可切换；术语在两种语言下都以 `GLOSSARY.md` 为准（英文名见词条）。用户自己输入的内容（应用名、描述、分叉原因等）不翻译。

## 应用

- 字段：应用标识（slug，全局唯一，创建后不可改）、显示名、描述、仓库关联、主线分支名（默认 `main`）、Owner 列表（≥1）、PE 列表（可为空）、部署相关信息（自由文本，PE 可编辑）。
- 一个应用对应一个仓库关联。
- 代码平台（类型 GitLab/GitHub + 实例地址 + 只读服务令牌）由管理员统一登记。建立仓库关联时选择平台、填写仓库，调用 API 校验，并保存项目 ID。

## 角色与权限

- 管理员：创建和删除应用，管理代码平台和用户。
- Owner：编辑应用，管理维护线和版本，增删 Owner/PE。
- 管理员也可以修改任何应用的 Owner/PE 名单，用于唯一 Owner 离职或长期不在时的移交（见 ADR-0003）。
- PE：对应用只读，可以编辑部署相关信息。
- Owner/PE 只能从已存在的用户中选择（LDAP 用户需要先登录一次）。

## 维护线与版本

- 只管理主线和维护线，不登记短期分支。
- 任何线上的任何版本都可以作为源版本，分叉出维护线；所有线构成一棵谱系树。
- 每个版本只属于一条线，版本号在应用内唯一，格式不强制。
- 版本字段：版本号、tag 或 commit、发布时间、说明。人工登记，不校验。
- 维护线字段：名称、Git 分支名、源版本、分叉原因（必填）、状态、备注，以及**可选**的计划终止日期。负责人沿用应用的 Owner/PE。
- 已终止维护线上的版本也可以作为源版本。
- 状态：活跃 → 冻结 → 终止，冻结可以回到活跃，终止不可逆。终止后只读，不可删除，不能合并回主线。主线没有状态。
- 维护线创建后，Owner 可以修改名称、备注、计划终止日期；Git 分支名、源版本、分叉原因不可修改。修改记入变更历史。
- 系统自动记录分叉时间和每次状态变更的时间，在维护线详情中展示。
- 冻结的线登记版本时说明必填；终止的线不能登记版本。
- 不追踪修复同步（cherry-pick），以后再做。

## 用户与登录

- 一个用户可以挂多个登录身份（LDAP 身份、邮箱身份），每种最多一个。邮箱身份用登录邮箱加密码登录，不能用用户名登录；登录邮箱在所有邮箱身份中唯一（2026-10-14 由“本地账号密码”改为邮箱身份，见 `docs/design/iam-scope.md`）。追加身份需要在已登录状态下主动绑定，或由管理员绑定。不按邮箱自动合并。
- 用户字段：用户名（唯一）、显示名、邮箱、手机号（可选）、部门（可选）、状态。绑定了 LDAP 的用户，显示名、邮箱、部门以 LDAP 为准，登录时同步。
- LDAP 只有一个，参数放在配置文件或环境变量中。首次启动时根据配置创建一个初始管理员，带一个邮箱身份，登录邮箱来自配置。
- 没有 LDAP 身份的用户可以修改自己的显示名、部门；绑定了 LDAP 的用户这两项只读。联系邮箱：绑定了 LDAP 的以 LDAP 为准，否则等于登录邮箱；第一期登录邮箱只能由管理员修改（用户自助修改需要邮件验证，在第二期）。手机号所有用户都可以改。管理员可以修改任何用户的这些字段（LDAP 管理的字段除外）。
- 不能解绑用户的最后一个登录身份。
- LDAP 用户优先占用用户名（ADR-0004）：LDAP 首次登录时用户名已被只有邮箱身份的用户占用，则拒绝登录，由管理员绑定身份或给该用户改名；管理员创建邮箱身份用户时先查 LDAP，同名用户名不允许创建。管理员可以修改没有 LDAP 身份的用户的用户名，内部关联一律用用户 ID。
- 用户只能禁用，不能物理删除。不能禁用某个应用的唯一 Owner，需要先移交。

## 其他

- 计划终止日期只作信息记录：在分叉对话框里是可选输入，在维护线详情里是一行普通字段。不做倒计时、提醒、按日期排序或变色，首页也没有相关内容。
- 审计日志：记录分叉、改动 Owner/PE、登记版本等操作，在应用详情页展示"变更历史"。

## 原型（/prototype）

纯前端，使用假数据，中英双语。已选定方案 A（Console）：左侧导航加窄顶栏，页面为表格和容器的组合，没有卡片套卡片。页面包括：

1. 登录页（LDAP 和邮箱切换）
2. 应用列表（搜索、我负责的应用、最新版本、维护线数量、Owner、仓库；列表下方是"最近活动"）
3. 应用详情，四个标签页：
   - 概览：应用标识、描述、仓库关联、主线分支、Owner/PE、部署信息、维护线摘要
   - 分支谱系：可展开的树形表格，选中一行后右侧面板显示该线的详情和版本；可选的图形列
   - 版本：本应用所有线上的全部版本，按线、tag/commit 筛选，可从版本直接分叉
   - 变更历史
4. 全局版本页：跨应用的版本列表
5. 分叉对话框、版本登记对话框
6. 个人设置：绑定和解绑登录身份、语言
7. 管理后台：代码平台、用户管理

原型代码在 `prototype/layout` 分支的 `web-prototype/`，不合入 main。
